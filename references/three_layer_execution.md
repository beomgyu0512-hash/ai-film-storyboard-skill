# 三层执行规则

各层统一采用“输入 → 处理步骤 → 输出 → 修改边界”。共同交接、检查与修改记录要求引用对应文件，不在各层重复维护。

## 一、叙事层（Microdrama）

### 1. 输入

- 用户提供的情节文本及创作要求。
- 已确认的故事设定和已有叙事成果。
- 本次需处理的问题；如为返修，读取问题表现及判断依据／原因假设。

### 2. 处理步骤

1. 明确故事目标、人物目标及本集／本幕承担的戏剧任务。
2. 理清事件因果和冲突成立条件。
3. 安排情绪转折与叙事节奏，落实任务所需的爽点、悬念和集末钩子。
4. 按[知识库调用规则](knowledge_call_rules.md)查阅相关资料。
5. 区分已确认内容与尚待确认的设计，按统一交接格式整理成果。

### 3. 输出

- 戏剧任务：事件、冲突、情绪转折及其节奏安排。
- 交接文件：在“已确认内容”中分别列明已定下的事件、冲突、情绪转折。

### 4. 修改边界

处理事件、冲突与情绪转折。已确认内容不得擅改；需要修改时，按交接文件的修改边界列明建议及上下游复查范围，交由用户决定。

## 二、导演层（Directing）

### 1. 输入

- 叙事层戏剧任务与交接文件。
- 已确认设定、用户要求及相关角色、场景资料。
- 用户选择从导演层进入时，读取已调整为对应输入格式的已有成果。

### 2. 处理步骤

1. 读取事件、冲突、情绪转折及已确认边界。
2. 安排观众何时知道什么、通过什么看到或听到，即信息揭示与观众视角。
3. 安排表演、停顿、场面调度和视听表达，明确期待的观众感受与情绪节奏。
4. 按[知识库调用规则](knowledge_call_rules.md)查阅相关资料。
5. 将戏剧任务转成拍摄方案，按统一交接格式交给分镜层。

### 3. 输出

- 拍摄方案：信息揭示、表演停顿、场面调度、视听安排和期待的观众感受。
- 交接文件：保留叙事层已确认内容，并分别补充已确认的信息揭示、表演停顿、期待的观众感受。

### 4. 修改边界

在交接允许的范围内设计表达方式。发现叙事问题时，先指出并反馈，不借“细化”擅改事件、冲突或情绪转折；修改按统一交接边界处理。

## 三、分镜层（Storyboarding）

### 1. 输入

- 导演层拍摄方案与交接文件。
- 正式分镜模板、已确认角色与场景参考。
- 用户选择从分镜层进入时，读取已调整为对应输入格式的已有成果。

### 2. 处理步骤

1. 读取导演方案及已确认的叙事、导演要求。
2. 将导演方案适当拆分为数个镜头，落实景别、构图、机位、运镜、动作、声音和衔接。
3. 明确每镜时长、起幅、落幅和切点；将导演层的停顿落实为具体时间安排与切镜位置。
4. 按[知识库调用规则](knowledge_call_rules.md)查阅相关资料。
5. 套用[分镜模板](../assets/storyboard_template.md)，每幕输出一个 MD；幕内明确标注“第几镜”，按模板分隔镜头。
6. 按[每幕分镜约束](scene_storyboard_constraints.md)依次执行检查与反馈，记录发现的问题。

### 3. 输出

- 每幕一个分镜 MD，包含逐镜内容、镜头时长和明确切点。
- 按检查约束标注检查状态及问题；发生修改时，更新专门的修改记录 MD。

### 4. 修改边界

落实导演方案，不擅改已确认的信息揭示、表演停顿或期待的观众感受。发现上游问题时，先反馈至最早出错的层；无法确定原因时标为“原因假设”，避免直接重写。

- 分镜格式：使用[分镜模板](../assets/storyboard_template.md)。
- 检查与反馈：使用[每幕分镜约束](scene_storyboard_constraints.md)。
- 修改记录：问题表现 → 所属层与依据 → 修改内容 → 修改后结果 → 是否值得改系统规则。
